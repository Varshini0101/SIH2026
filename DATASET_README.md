# Dataset and Data Layer README

## Scope

This repository is intentionally kept in the foundation/MVP phase. The data layer supports a basic, explainable cybercrime complaint workflow:

- complaint records
- account records
- transaction risk review
- suspicious activity classification
- ATM/POS location context
- basic withdrawal prediction
- risk explanations for an investigator dashboard

## Core principle

The project does not claim to use real NCRP complaint data or real Indian banking/ATM withdrawal records. Instead, it follows a factually defensible architecture:

public fraud data + public geographic data + derived transformations + synthetic demo layer

## Dataset categories

### Public / real data

- IEEE-CIS Fraud Detection (public transaction fraud reference)
- Credit Card Fraud Detection (public anonymized fraud-pattern benchmark)
- OpenStreetMap (public spatial/geographic reference)

### Derived data

- Complaint-to-transaction bridging rules
- Risk explanation templates
- Candidate withdrawal-location mapping based on suspicious account behaviour and geography

### Synthetic data

- Complaint records that mimic investigator case workflows
- Account and transaction sequences used to exercise the app end-to-end
- Withdrawal and ATM/POS records used in prediction and map visualisation

## Data folder structure

- data/raw/public/ - public reference datasets or metadata
- data/raw/external/ - external map or reference datasets
- data/raw/synthetic/ - synthetic records kept as demo source data
- data/processed/ - normalized internal records
- data/derived/ - derived relationships and rules-based transformations
- data/documentation/ - validation and source notes

## Data flow into the application

1. Public fraud datasets are used to identify behavioural risk patterns and transaction anomaly characteristics.
2. OpenStreetMap provides geographic context for ATM/POS locations and risk hotspots.
3. The derived layer creates a complaint-to-account-to-transaction narrative that is traceable but clearly not copied from a real NCRP dataset.
4. The synthetic layer powers the application’s end-to-end demo workflow and ensures the MVP remains functional without external API access.
5. The backend API serves normalized records to the frontend without exposing raw file internals directly.

## Synthetic augmentation rules

The synthetic layer is generated with internal consistency:

- complaint -> suspected account
- account -> related transactions
- suspicious account -> probable withdrawal behaviour
- withdrawal -> ATM/POS location
- prediction -> complaint + candidate ATM/POS

These relationships are explicit and traceable, and they are clearly labelled as synthetic.

## Validation expectations

The dataset pipeline should validate:

- duplicate IDs
- valid amounts
- valid timestamps
- valid coordinates
- foreign key consistency across complaint/account/transaction/withdrawal/prediction records
- balanced suspicious vs normal transaction counts in the demo layer
- clear separation between public reference data and synthetic workflow data

## Application consumption

The frontend consumes REST API responses. The backend acts as the stable interface between the application and the underlying dataset layers.

## Limitation statement

- This is not a live NCRP, CFCFRMS, or real banking production dataset.
- It is designed for explainable MVP workflow and foundation validation.
- It is not presented as operational intelligence.

The prototype is intentionally built for future ML extension, while maintaining a transparent and auditable data story for judges and future developers.

## Separate ML foundation corpus

The existing small synthetic dataset remains the UI/demo dataset. A separate reproducible ML corpus is generated by `node data/pipeline/generateSyntheticML.mjs` and does not replace the dashboard data.

- 600 cases
- 5,090 transactions
- 598 withdrawal events
- 120 synthetic ATM/POS locations
- 4,800 candidate ATM records
- deterministic TRAIN/VALIDATION/TEST case split of 420/90/90

The ML corpus contains explicit cash-out ground truth and is labelled SYNTHETIC. Public fraud datasets are not claimed to contain ATM withdrawals or NCRP relationships.
