# Unified Feature Schema

The ML pipeline uses one row per case in `data/processed/ml_training.csv` and one row per case/ATM candidate in `data/processed/atm_ranking_candidates.csv`.

## Case and labels

| Field                    | Meaning                                              |
| ------------------------ | ---------------------------------------------------- |
| case_id                  | Stable synthetic case identifier                     |
| complaint_id             | Synthetic complaint identifier for the case          |
| fraud_label              | 1 for generated fraud cases, otherwise 0             |
| cashout_label            | 1 when a ground-truth withdrawal exists, otherwise 0 |
| pattern                  | Generated behaviour pattern                          |
| actual_withdrawal_atm_id | Ground-truth ATM/POS ID, null when no cash-out       |
| actual_withdrawal_time   | Ground-truth withdrawal timestamp                    |
| actual_withdrawal_amount | Ground-truth withdrawal amount                       |
| time_to_cashout          | Minutes from complaint event to actual withdrawal    |
| split                    | TRAIN, VALIDATION, or TEST                           |

## Transaction features

- `transaction_count`: number of transactions in the case sequence
- `suspicious_transaction_count`: number of transactions labelled suspicious/fraudulent
- `transaction_frequency`: sequence transaction count normalized by 24 hours
- `transaction_velocity`: transaction count per active sequence hour
- `amount_deviation`: mean transaction amount in the sequence

## Sequence features

- `hop_count`: number of account-to-account transfer hops
- `unique_accounts`: distinct accounts appearing in the sequence
- `transfer_chain_length`: number of accounts in the generated chain
- `amount_decay_across_hops`: final chain amount divided by starting amount
- `rapid_transfer_flag`: 1 for the rapid-transfer pattern

## Account features

- `account_activity_frequency`: transaction count per source account in the sequence
- `account_risk`: generated LOW, MEDIUM, or HIGH account risk band
- `new_destination_flag`: whether multiple new destination accounts appear
- `destination_concentration`: mean transactions per distinct destination account

## Temporal features

- `hour`: UTC hour of actual withdrawal when available
- `day_of_week`: UTC day of actual withdrawal when available
- `time_since_last_transaction`: minutes from last chain transaction to withdrawal
- `time_since_first_suspicious_transaction`: minutes from first suspicious transaction to final chain activity
- `time_since_fraud_event`: minutes from complaint/fraud event to cash-out

## Withdrawal history features

- `previous_withdrawal_count`: prior withdrawals in the generated case history
- `average_withdrawal_amount`: mean previous/actual withdrawal amount
- `time_since_previous_withdrawal`: interval from a previous withdrawal when available

## Candidate ATM features

`atm_ranking_candidates.csv` contains:

- `distance_from_last_activity`
- `distance_from_previous_withdrawal`
- `regional_match`
- `time_compatibility`
- `historical_area_score`
- `is_actual_withdrawal`

The candidate label is ground truth generated by the simulator. It is not a model prediction.

## Leakage boundary

The case-level training CSV contains pre-withdrawal features and the explicit classification labels `fraud_label` and `cashout_label`. The following are targets or audit fields, not model inputs: `actual_withdrawal_atm_id`, `actual_withdrawal_latitude`, `actual_withdrawal_longitude`, `actual_withdrawal_time`, `actual_withdrawal_amount`, and `time_to_cashout`. They are stored in `ml_cases.csv` and `ml_withdrawals.csv`.

Public normalized records use the common schema `transaction_id`, `case_id`, `timestamp`, `amount`, `transaction_type`, `source_account`, `destination_account`, `fraud_label`, `cash_out_label`, `account_age`, `transaction_velocity`, `transaction_frequency`, `balance_delta`, `sequence_position`, `location`, `source_dataset`, and `source_type`. Fields absent from the original source are null; derived fields carry provenance notes.
