# Data Foundation Handoff

## Stable inputs

All files below are generated by `node data/pipeline/generateSyntheticML.mjs` and are independent of the existing UI/demo dataset.

## Member 2: fraud and cash-out modelling

Use:

- `data/processed/ml_training_train.csv`
- `data/processed/ml_training_validation.csv`
- `data/processed/ml_training_test.csv`
- `data/processed/ml_transactions.csv`

Classification labels are in `fraud_label` and `cashout_label`; case ground truth is in `actual_withdrawal_time`, `actual_withdrawal_amount`, `hop_count`, and `time_to_cashout` in `ml_cases.csv`. Split by the supplied `split` field; do not regroup individual transactions across cases.

`ml_training_train.csv`, `ml_training_validation.csv`, and `ml_training_test.csv` contain pre-withdrawal features plus `fraud_label` and `cashout_label`. Actual ATM/time/amount and `time_to_cashout` are intentionally excluded from those feature files to prevent future-information leakage. Read those targets from `ml_cases.csv` for evaluation.

## Member 3: ATM ranking

Use:

- `data/processed/atm_ranking_candidates.csv`
- `data/processed/atm_locations.csv`
- `data/processed/ml_withdrawals.csv`

Rank candidate ATM records using the feature columns. Evaluate against `is_actual_withdrawal`. The true withdrawal is also available in the case-level ground truth for audit.

## Members 4-6

Use:

- `case_id` as the cross-module join key
- `complaint_id` for complaint references
- `transaction_sequence` and `ml_transactions.csv` for evidence trails
- `fraud_label`, `cashout_label`, `time_to_cashout`, and `actual_withdrawal_*` for evaluation and downstream metadata
- `split` to preserve evaluation boundaries

No alerting, model, ranking, or investigator recommendation logic is implemented in this data foundation module.

## Existing API compatibility

The current API continues to use `backend/data/demoData.js`, `backend/services/databaseService.js`, and the existing MongoDB seed path. The ML files are offline artifacts and are not imported by the dashboard controllers.

## Public normalized data

Run `npm run normalize:public` after placing licensed downloads in `data/raw/public/paysim/`, `data/raw/public/ieee_cis/`, or `data/raw/public/credit_card_fraud/`. The output is `data/processed/public/public_transaction_normalized.csv`; missing fields remain null and no public row receives a synthetic complaint, ATM, or cash-out relationship.
